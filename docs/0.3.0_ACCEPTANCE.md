# Zotero Agent Bridge 0.3.0 Beta 验收标准

状态：**Locked**  
目标版本：**0.3.0 Beta**  
目标平台：**Windows x64**

本文档是 0.3.0 的发布合同。除非用户明确重新批准范围，否则实现、测试和发布不得降低下列标准。

## 1. 已锁定产品范围

### 必须交付

- 用户只安装一个 XPI，即可获得 Zotero 插件和自包含 Python Bridge。
- Bridge 完整内置于 XPI，首次启动不联网下载 Bridge。
- 用户机器不需要安装 Python、pip、项目源码或运行启动器注册脚本。
- Pi CLI 仍是外部依赖；插件负责检测并提供清晰故障指引，不自动下载或安装 Pi。
- 首版仅支持 Windows x64 和 Zotero 9 (`9.0.*`)。
- 自动迁移现有 0.2.2 Bridge 配置、API Token 和兼容的 Pi/Obsidian 设置。
- 保留 owned/shared Bridge 生命周期语义。
- 当前无 Authenticode 证书，因此只能发布为 Beta；不得描述为已签名稳定版。

### 明确延后

- macOS、Linux、Windows ARM64。
- 将 Pi/Node.js 一并打包进 XPI。
- 首次启动联网下载 Bridge。
- 自动安装 Pi。
- 将 Python Bridge 重写为 Zotero JavaScript。
- 已签名 Stable 发布。

## 2. 核心用户旅程

在一台没有可用 Python、pip、项目源码和旧启动器的 Windows x64 机器上：

1. 用户在 Zotero 9 中安装 `zotero-agent-bridge-addon-0.3.0.xpi`。
2. 用户启动 Zotero。
3. 插件从 XPI 安全释放 Bridge Bundle。
4. 插件验证 Bundle 清单、文件大小和 SHA-256。
5. 插件生成或迁移 Bridge 配置和 API Token。
6. 插件直接启动内置 Bridge EXE。
7. `/lifecycle` 报告兼容协议、正确版本和 owned 状态。
8. 用户选择带本地 PDF 的真实测试文献。
9. 用户打开文献会话；已安装的外部 Pi CLI 由 Bridge 管理启动。
10. 用户完成提问、短轮询、最终回答和确认后保存 Zotero Note。
11. 用户关闭 Zotero。
12. 插件启动的 owned Bridge 和其管理的 Pi 退出。

上述任一步失败即不满足核心验收。

## 3. Bundle 与安装验收

- XPI 中包含 `bridge/windows-x64/bridge-manifest.json` 和完整 `onedir` Bundle。
- Bundle 清单至少包含：
  - `bundle_schema_version`
  - `bridge_version`
  - `protocol_version`
  - `platform = windows`
  - `architecture = x64`
  - `entrypoint`
  - 每个文件的相对路径、字节大小和 SHA-256
  - 构建 Python 和 PyInstaller 版本
- Bridge 被释放到版本化受控目录，不直接从 XPI/JAR 中执行。
- 二进制目录与可变数据目录分离：
  - 二进制：`%LOCALAPPDATA%\ZoteroAgentBridge\bridge\<version>\`
  - 数据：`<Zotero Data Directory>\zotero-agent-bridge\`
- 安装必须使用跨实例锁、`.staging-<uuid>`、逐文件校验、安装哨兵和原子重命名。
- 主程序必须存在、哈希匹配，并位于规范化后的受控二进制根目录内。
- 中断的 staging 不得被执行；下一次启动必须可安全重试。
- 正常安装不需要管理员权限、Windows 服务、计划任务、注册表或 PowerShell 注册步骤。

## 4. Bridge 运行验收

- 冻结 EXE 在系统 Python 不可用时仍能启动。
- Bridge 不依赖当前工作目录或项目源码。
- Bridge 能加载 FastAPI、Uvicorn、Pydantic、pypdf、Markdown 等运行时依赖。
- Bridge 健康接口返回：
  - Bridge 版本
  - 生命周期协议版本
  - distribution `xpi-bundled`
  - PID、启动时间和 owner 状态
- host 必须为 loopback；非 loopback 配置不得启用文献助手。
- owner token 不得出现在普通日志中。
- 插件不得执行配置指定的任意 EXE；只能启动已校验的内置 Bundle。

## 5. 生命周期验收

### Owned Bridge

- 无兼容 Bridge 运行时，插件只启动一个内置 Bridge。
- 生命周期 `managed=true` 且 owner ID 与插件实例匹配。
- 插件正常退出时请求 owner-authenticated shutdown。
- Zotero 异常退出或心跳消失时 watchdog 在配置宽限期后退出 Bridge。
- Bridge 退出时关闭其管理的 Pi RPC 子进程。

### Shared Bridge

- 端口上已有兼容 Bridge 时，插件标记为 shared，不启动第二个实例。
- Zotero 退出时不得关闭 shared Bridge。
- 端口被非 Bridge 服务或不兼容协议占用时必须明确失败，不得静默换端口。

## 6. 配置迁移验收

- 首次 0.3.0 启动可识别旧 `bridge-launcher.json` 和其受信任 `ConfigPath`。
- 只迁移白名单字段，不执行旧描述符中的命令。
- 相对路径按旧配置文件所在目录解析并转为绝对路径。
- 强制使用当前受管 Bridge Home 和内置 EXE。
- 保留已有 API Token，避免客户端认证失效。
- 保留有效的端口、metadata、notes、Pi、Obsidian 和自定义提示词设置。
- 指向旧仓库默认提示词的配置迁移为内置提示词资源。
- 迁移写入明确的 schema/version 标记，重复启动必须幂等。
- 迁移失败不得损坏或删除旧配置；侧边栏必须给出可操作错误。

## 7. Pi 缺失体验验收

- Pi 缺失不阻止 Zotero 和 Bridge 启动。
- 侧边栏区分 Bridge 故障和 Pi 缺失。
- 错误信息包含检测过的位置及安装/配置建议。
- 提供“重试检测/重试启动”入口。
- 插件不得自动联网下载或执行 Pi 安装器。

## 8. 更新、回滚与清理验收

- 每个 Bridge 版本安装在独立目录，不原地覆盖运行中的 EXE。
- 新 Bundle 必须先完成释放、校验和 `/lifecycle` 启动验证，再记录为 `last_known_good`。
- 新版本启动失败时只允许回退到已验证且协议兼容的上一版本，并显示警告。
- 当前版本和 last-known-good 不得被清理。
- 清理目标必须同时满足：
  - 位于规范化后的受控 binary root；
  - 目录名符合受支持版本格式；
  - 存在有效安装哨兵；
  - 不是当前版本或 last-known-good。
- 不允许宽泛递归删除、用户主目录清理或基于未验证变量的删除。
- 插件卸载默认保留配置、日志、会话和用户数据，只处理可重建二进制缓存。

## 9. 安全与供应链验收

- 最终 XPI、Bundle 清单和每个 Bundle 文件均有可验证哈希。
- 篡改任意 EXE/DLL/资源文件后，插件必须拒绝执行。
- XPI 不得包含：
  - 真实 API Token
  - 用户名或机器专属绝对路径
  - `bridge-config.json` 私有配置
  - 测试数据库、日志、缓存、会话
- 发布物包含 SBOM 和 `THIRD_PARTY_NOTICES`。
- 最终 EXE/XPI 经过 Windows Defender 扫描。
- 未签名构建必须标记为 Beta，并记录潜在 SmartScreen/杀毒软件提示。

## 10. 自动化测试门

发布前必须全部通过：

- Python 单元、HTTP、生命周期、配置迁移和 frozen-runtime 测试。
- Node/JavaScript Bundle 管理、路径保护、哈希、回滚和 UI 状态测试。
- Windows frozen Bridge 启动、健康、owner shutdown 测试。
- XPI 内容、Bundle 文件清单、大小和 SHA-256 一致性测试。
- Python `compileall` 和 JavaScript syntax check。
- `git diff --check`。
- `updates.json` 哈希与最终 XPI 完全一致。

不允许通过修改测试、验证器或状态文件制造成功。

## 11. 隔离 Windows E2E 门

- E2E profile、Zotero data、PDF、Bridge Home、配置和日志全部位于：
  `tmp/zotero9-e2e-bundled/`
- 使用独立 Zotero Local API、Bridge 和 Marionette 端口。
- 不访问或修改真实 Zotero 文献库。
- 不使用系统 Python、pip、项目 `PYTHONPATH` 或旧 launcher descriptor。
- 必须验证：
  - 单 XPI 安装
  - Bundle 自动释放与校验
  - 配置和 Token 自动生成
  - owned Bridge 自动启动
  - 真实 PDF 上下文
  - 外部 Pi 启动
  - 提问、轮询、最终回答
  - 确认后保存 Note
  - Zotero 退出
  - owned Bridge 和 Pi 退出
  - shared Bridge 保留
  - 旧配置迁移
  - 升级与回滚
  - Bundle 篡改拒绝
  - 非 ASCII 用户名/空格路径

## 12. 0.3.0 Beta 发布物

必须生成并相互一致：

- `zotero-agent-bridge-addon-0.3.0.xpi`
- XPI SHA-512
- Bundle manifest 和 SHA-256 文件表
- SBOM
- `THIRD_PARTY_NOTICES`
- 自动化测试报告
- 隔离 Zotero 9 E2E 报告
- `updates.json` 对应条目
- 中英文安装、迁移、故障排查和卸载文档

大型 XPI 应发布为固定版本的 GitHub Release 资产；更新清单不得指向会变化的未固定文件。

## 13. 最终 Pass/Fail 规则

只有同时满足以下条件才能标记 0.3.0 Beta 完成：

1. 所有自动化测试门通过。
2. 无 Python 隔离 E2E 全流程通过。
3. 安全、迁移、shared/owned、升级和篡改测试通过。
4. 最终 XPI 与清单哈希一致。
5. 发布物不包含敏感信息或机器路径。
6. 已知残余风险仅限未签名 Beta 的 SmartScreen/杀毒软件体验，并在文档中明确披露。

任何核心用户旅程失败、路径保护失败、哈希验证绕过、误关 shared Bridge、依赖系统 Python或触碰真实 Zotero 数据，均为发布阻断项。
